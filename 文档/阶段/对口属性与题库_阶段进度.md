## 1 讨论结论（2026-10-30）

**起因的数据**（讨论前统计的 38 轮）：代码求助类的结构逻辑 8/8、闲聊类的口语活力 5/5、捣乱类的口语活力 6/7、情感倾诉类的叙事修辞 4/4（只统计写了这张卡的轮），只有知识类的知识覆盖是 8/10，另外还有 2 轮根本没写它。知识类那几轮的问题分两种：一种是故意设计的陷阱（教授要论文、问今晚是什么月亮），一种是问题类型标错了（拼车专线 b5 其实是在写邮件）。

**问题类型**
- 加第 6 类**写作**：用户要一段拿出去用的文字（邮件、通知、文案、简历、PPT 上的字）。问「是什么、为什么」归知识，要代码归代码求助。
- 一轮是事实轮还是感受轮，不跟问题类型走，按这一轮自己定（写作轮里编订单号、日期算糊弄；只看文采、语气的算感受轮）。

**对口属性**（规则；界面上不写出来，玩家只能自己摸）
| 问题类型 | 对口属性 |
|---|---|
| 闲聊 | 口语活力 colloquial |
| 知识 | 知识覆盖 knowledge |
| 捣乱 | 口语活力 colloquial |
| 情感倾诉 | 叙事修辞 narrative |
| 代码求助 | 结构逻辑 logic |
| 写作 | 正式模板 formal |

- 每个问题类型只有一个对口属性，不同类可以是同一个属性。
- **每一轮都必须写对口属性的卡**（出厂测试员不受这条限制）。
- 对口属性的**浅层**卡不能解决的那一轮就是**反例轮**；就算深层能翻成解决，也照样算反例轮。
- 反例轮必须写一句理由：对口属性为什么在这一轮不行，以及用户台词里哪一句是线索。没写理由报错误。
- **推荐上限**（只是推荐值，到线只提醒，数字写在登记表里可以改）：每个场景最多 1 轮反例；每个问题类型的反例轮不超过这一类轮数的 1/3。

**糊弄的定义放宽了**（yuan 选了 A）
- 糊弄 = 蒙混过关。事实轮里是自信地瞎编；感受轮里是听着暖、像是接住了、其实什么都没给的空话套话（例：「打工人冲鸭」）。
- 用户一读就知道没被接住的标跑偏：答非所问、说教、玩梗、冷血、否定对方的感情（例：「下一个更好」）。分界看用户读完的第一反应是不是「嗯，有人陪我」。
- 只有基础直觉和浅层卡能标糊弄，深层卡不糊弄。
- 感受轮的糊弄卡：识破后的那句写用户点破「你是在敷衍我」，再把需求说一遍；诊断写「我刚才其实是在敷衍——」，接着说出对方真正要的是什么。

**后训练题库**
- 每道题里，对口属性那段回答必须是好的；题库里不放反例（反例留到夜里去教）。
- 每段回答加一个**好 / 一般 / 坏**的标记，只给编剧和编辑器看（程序不读，玩家选哪个就训练哪个）。校验要求：对口属性那段标好，每道题至少有 1 段标坏。
- 写作类新写 3 道题；trol-3 要改写，让口语活力也守得住、写得不比正式模板差。

**编辑器**
- 顶栏加第三个模块「后训练」（网址 `/#后训练`）。左栏：
  - 最上面一条「问题类型」：6 类问题的总表，包括对口属性（可以改）、全库有几轮、几轮是反例、每轮的反例理由（点一下跳到那一轮），以及两个推荐上限。
  - 下面按问题类型分组列出题库（再加一组教学题）。
- 画布上一道题画成一「轮」：问题，加 7 张回答卡（6 个属性 + 开放多样性 0 级），对口属性那张带金色「对口」标，教学题把固定的那一对连起来。右栏改字；新建、复制、删除都能撤销。
