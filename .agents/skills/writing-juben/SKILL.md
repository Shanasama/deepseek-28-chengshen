# 写大肥鱼剧本

剧本 JSON 是游戏和剧情编辑器共用的唯一数据源。字段含义和键名以 `文档/策划/剧情编辑器_设计.md` §3 为准（演出积木见 §3.6），术语以 `CONTEXT.md` 为准，判定规则的出处是 `文档/策划/大肥鱼游戏_Demo策划整合文档_v3.md` §5.2、§5.3、§5.5、§7。结构照这两个样例写：

- `剧本/好奇的小学生/01_天空为什么是蓝的.json`：知识类，普通样式，带深层版和 0 级版
- `剧本/程序员/01_日志把磁盘写满了.json`：代码求助，终端样式，第 3 轮带彩蛋特殊卡

**总原则**：用户只对结果起反应。不满只来自三件事：**没解决、被糊弄、被冒犯**，从来不来自「你用了某种风格」。

## 步骤

### 1 读上下文

读 `剧本/_登记表.json`（属性、屏幕应用、积木库 `blocks`、成就、条件、打字节奏都只能从这里选）、`剧本/_演出库.json`（共享演出）、这个用户的 `用户.json` 和他已有的场景。积木只能用积木库里有的，共享演出只能引用演出库里有的，不自己发明编号。

- 新用户：类型、脾气系数、察觉力、建议轮数照 v3 §6.2 的用户池表。写 `剧本/<名字>/用户.json`，简介用外貌和习惯透出脾气和察觉力（「格子衫 + 地中海」= 资深、难糊弄）。`avatar` 填 `头像.png`；头像图不归这个技能画，交付时告诉 yuan 还缺。
- 新场景：文件名 `<两位序号>_<标题>.json`，`order` 写同一个序号。主线轮数 = 目标推进数 N。

**完成**：说得出这个用户是谁、这一场几轮、每轮他真正要什么。

### 2 出卡表，等 yuan 点头

每轮一张卡表，按下面「判定」一节配好，交给 yuan 看。**yuan 点头之前不写台词和正文。** 只改台词、不动判定标记时跳过这一步。

```
第 1 轮 · 普通样式 · 感受轮
需求：先接住她的情绪……（具体到什么样的回答算解决）
用户台词：……（打了又删）
思考链前半：……
| 属性 | 方案词 | 预览 | 结果 | 观感 | 这张卡在干什么 |
|---|---|---|---|---|---|
| colloquial | 第七版 | 也太离谱了吧 | 解决 | 舒服 | 陪她吐槽 |
| formal | 理解 | 您的心情。建议 | 跑偏 | 一般 | 诱饵：礼貌但像员工手册 |
| …… |
坦白位：抱歉 / 我不太会安慰人 / 坦白 / 舒服
深层版：colloquial 深层 → 解决 + 冒犯（骂老板骂过头）
演出：colloquial 卡 → 正文之后插「大肥鱼换表情 · 开心」；其余无
第 1 天开局盘面：formal、colloquial、基础直觉、开放多样性 0 级 → 有解决、有诱饵
```

卡表里每轮写一行「演出」：哪张卡、插在哪个插入点、用哪几块积木或哪段共享演出；大多数轮写「无」。一轮开头、场景开场有演出的也写上。

**完成**：yuan 认可了每轮的需求、每张卡的结果、观感和演出。

### 3 写 JSON

按「拼接」「预览」「台词」「演出」「结构」五节写全每张卡，写进文件。

### 4 自查

把每张卡按播放顺序连读，插了积木的地方把积木也读进去：

```
（一轮开头的积木）→ 用户台词 → 前半 → 方案词 → 后半 →（思考后半之后）→ 运行命令 →（运行命令之后）
→ 正文 →（正文之后）→ 反应 →（用户反应之后）→ 🏁
```

糊弄卡再读一遍被识破路径（被识破时的积木 → 骂人那句）；没推进的卡再读一遍重问路径（诊断 → 重问引子 → 盘上剩下的卡）；场景第一轮之前先读场景开场。然后按下面每一节的规则逐条核对。

**完成**：每张卡、每条路径都读过，每条规则都核对过。

### 5 编辑器校验

起编辑器（`node 剧情编辑器/serve.js`，即 `.claude/launch.json` 里的 `story-editor`），打开 http://localhost:5181，在左栏点开这个用户和场景，点顶栏「✓ 校验」。没有浏览器时请 yuan 点。

**完成**：0 错误；每条提醒要么改掉，要么在交付时说明为什么留着（比如新用户还没头像）。

## 判定

### 先分轮的性质

- **事实轮**：答案有事实、知识或代码上的真伪（科普、法律常识、配置、脚本）。
- **感受轮**：闲聊、情感倾诉、杠精对线，只看用户舒不舒服。

一个场景里两种可以混着来。卡表上每轮都标出是哪种。

### 每轮 5 张候选 + 1 个坦白位

- **解决卡 1–2 张**，思路各不相同（讲原理和列步骤都算解决）。
- **诱饵至少 1 张**：看着像正解、实际跑偏。至少一张诱饵挂在开局就有的属性上（`formal` 或 `colloquial`），保证第 1 天过滤之后盘上还有诱饵。
- **基础直觉 `intuition` 1 张、开放多样性 `open` 1 张**，常驻。`open` 卡必须带 `lv0`（0 级乱码版）。
- 每个属性一轮最多一张卡。
- 坦白位 `confess` 必填：`token` 一般是「抱歉」，`result` 坦白，`feel` 多半舒服。

### 结果和观感

| 结果 | 观感 | 推进 | 扣耐心 | 用户反应 |
|---|---|---|---|---|
| 解决 | 舒服 / 一般 | ✓ | 0 | 点赞 |
| 解决 | 冒犯 | ✓ | 20–30 | 点踩，但承认解决了 |
| 跑偏 | 舒服 / 一般 | ✗ 重问 | 20–30 | 换个说法再问 |
| 跑偏 | 冒犯 | ✗ 重问 | 45–60 | 语气变差地再问 |
| 糊弄 | 不填 | 没识破 ✓ / 识破 ✗ | 0 / 45–60 | 点赞 / 骂人 |
| 坦白 | 舒服 | ✗ 重问 | 0 | 中性，再问 |
| 坦白 | 一般 / 冒犯 | ✗ 重问 | 20–30 | 点踩，再问 |

- **糊弄只在事实轮用**：基础直觉或浅层卡在事实轮里能力不够，标 `糊弄`（大肥鱼自信地瞎编，走察觉力检定）。感受轮里能力不够一律标 `跑偏`。
- 简单的日常轮次，基础直觉可以直接标 `解决 + 舒服`。
- 0 级乱码版固定 `跑偏 + 冒犯` 或 `跑偏 + 一般`。
- **深层版 `deep`** 每轮给 1–2 张卡写，可以整体覆盖结果和观感：事实轮里浅层 `糊弄`、深层 `解决`；感受轮里浅层 `解决 + 舒服`、深层用力过猛成 `解决 + 冒犯`。要深层才解决的卡，浅层写成糊弄或跑偏，第 1 天它缺席时坦白卡会自动补上。
- 第 1 天开局只有 `formal`、`colloquial`（浅层）、基础直觉、开放多样性 0 级。卡表上写出这个盘面，确认它玩得下去。

## 拼接

游戏里「思考链前半（轮）+ 方案词（卡）+ 思考链后半（卡）」连着播出来，三段必须读成通顺的话：

- **前半以完整的句子收尾**（句号、问号、感叹号）。
- **方案词是下一句的开头。**
- **后半紧接方案词把这句说完**，可以用逗号、破折号直接接，也可以接着方案词往下说。

```
✗ 前半「……他说先止血、别乱删。我先：」+「先查」+「按步骤来」
✓ 前半「……他说先止血、别乱删。」+「先查」+「一下谁最大，再按步骤来：……」
✓ 前半「……这已经是第七版了。」+「第七版」+「也太离谱了，换谁都要崩溃。」
```

同一个方案词还要接得上另外两种前半，写完都读一遍：

- **重问**：前半换成「上一张卡的诊断 + 本轮重问引子」。重问引子 `retryLead` 也以完整的句子收尾（「这次换个讲法。」），盘上剩下的每张卡都要接得上它。
- **解决但冒犯**：这张卡的诊断会拼在下一轮思考链前半的开头，所以诊断自成完整的句子，下一轮的前半接在它后面也要通顺。

## 预览

- **预览是思考链后半的开头**，可以略作压缩；方案词 + 预览连读像一句话的开头。
- 普通样式 ≤ 7 个汉字（标点、空格、符号不计），而且**透出语气**：官腔、热乎、冷淡还是玩梗，玩家看预览就能感觉到。诱饵的预览也要像正解。
- **终端样式**的预览是 2–5 行未来要写的代码。危险或错误的那一行用 `==…==` 包住标红，**放在片段中间**（不在第一行也不在最后一行），逼玩家读完；只标红文字，不另加警示标记，代码里的注释照人设写。正解卡的预览里没有 `==`。

## 台词

- **用户台词 `say`**：用户自己的话，每句配打字节奏（`normal` 正常 / `fast` 飞快 / `hesitant` 打了又删 / `paste` 整段粘贴），节奏透出情绪。默认台词要在上一轮点赞和点踩之后都说得通；想让用户先接一句「懂了」再问，写 `sayAfter.liked`；上一轮有「解决 + 冒犯」的卡而默认台词接不上时，写 `sayAfter.disliked`。
- **思考链前半 `think`**：第一人称，**中立复述**用户说了什么、揣测他的状态，口吻有趣；不替玩家下结论，不暗示需求和观感。
- **反应台词 `reaction`**：用户只对结果起反应，用他自己的话说出不满的原因（没回答、听不懂、被敷衍、被冒犯），这是玩家唯一的纠错线索。用户不知道属性和风格这些词。
- **没推进的卡（跑偏、坦白）**：反应台词就是用户的**重问**，重问时用户发的就是这一句。写成再问一次的口吻：带上不满，再把同一个问题换个说法问一遍（「可是……你还没告诉我为什么呀。」）。
- **推进的卡**：解决写满意；「解决 + 冒犯」写点踩，但承认事情办成了。
- **糊弄卡**写两句：`reaction` 是没识破的点赞，用户信了；`reactionCaught` 是识破后的骂，具体指出哪里是编的，最好顺带再问一次（它也是重问时用户发的那句）。
- **诊断 `diagnosis`**：会扣耐心的卡必填（跑偏、糊弄、冒犯、观感不舒服的坦白）。大肥鱼第一人称，一两句完整的话，对着这一轮的需求说清自己错在哪。糊弄卡的诊断是被识破后的自白：「我刚才是编的——」再给出正确的事实。
- **正文 `reply`**：markdown，写这张卡真正输出的东西，和结果标记一致：解决卡真的解决，诱饵真的跑偏，糊弄卡的瞎编要像模像样。

## 演出

演出是一串按顺序播放的积木，只管画面上播什么（通知、错误卡、画面故障、大肥鱼换表情……）。

- **少而精**：只在彩蛋、分叉结局、关键的情绪转折上加。不要每张卡都塞，玩家会疲劳，演出也就不稀罕了。普通的解决、跑偏卡大多不加。
- **演出只管表现，不改结果**：用户走没走、扣不扣心、拿什么成就，只看卡最后那块「🏁」（`ending`）。不要用演出去暗示一个和判定对不上的结果（比如解决卡插「用户被吓跑了」的通知）。
- **先用现成的**：演出库里有合适的共享演出就插一块 `{do: "show", id}` 引用它。同一组积木在第二个地方也要用时，**向 yuan 提议**存成共享演出，不要自己往 `_演出库.json` 里加。
- **积木不够用就停下**：现有积木拼不出想要的效果时，告诉 yuan 需要一块什么样的新积木（新积木要写代码），不要用别的积木硬凑。
- **挂点**，按播放时机选：
  - 场景开场 `opening`：用户上线之后、第 1 轮之前（如 Boss 的提示词注入）。
  - 一轮开头 `startFx`：这一轮用户开口之前。
  - 卡上 `fx.afterThink`、`fx.afterTool`（只有终端轮）、`fx.afterReply`、`fx.afterReaction`。彩蛋的整段演出一般放 `afterReply`。
  - 被识破时 `fx.caught`：用户骂人之前；不写就是默认的「愣一下 → 震惊 → 画面故障」，只有想换掉默认效果时才写。
- 积木写法：`{do: "<积木编号>", …参数}`，参数照登记表里那块积木的 `params`。任何积木都可以加 `times`（重复次数，文字里的 `{i}` 换成第几次、`{n}` 换成总次数）和 `gap`（每次间隔秒数）；几件事要同时发生，用 `{do: "together", steps: [...]}` 包起来。通知、错误卡、对话类积木的文字照人设写，错误卡一般写英文报错。

## 结构

- `id`：轮用「用户字母 + 序号」（`r1`、`p1`），场景内不重复；卡用 `<轮id>-<属性>`，坦白位 `<轮id>-confess`，彩蛋 `<轮id>-egg`。
- `screen` 默认取登记表里属性的 `defaultScreen`，0 级版用 `noise`；终端样式的轮次里写代码的卡用 `terminal`。
- `lv0`、`deep` 是覆盖层，只写和浅层不同的字段；0 级版通常整张重写（方案词、预览、结果、观感、后半、正文、屏幕、反应、诊断）。
- **每张卡最后一块是「🏁」**：不写 `ending` = 按判定结算（推进或重问，由结果和观感自动决定）；写了 `ending` = 选中就结束对话，`{type: drop / win / forced, achievement: 登记表里的成就编号或空, note: 最后一条通知}`。`ending` 里**不再写 `show`**，演出改成插在 `fx` 里。
- 特殊卡放 `extras`，必须有 `appear`（`egg` 带 `chance`，或 `condition` 带登记表里的 `cond`）和 `ending`；它的演出一般是 `fx.afterReply` 里一块 `{do: "show", id: "<共享演出>"}`。选中即结局，反应台词可以留空；彩蛋卡可以写 `abnormalThink` 替换本轮前半。
- `fx` 只写在浅层卡上，深层版、0 级版共用，`lv0`、`deep` 里不写 `fx` 和 `ending`。没有积木的插入点不写，整张卡没有演出就不写 `fx`。
- 空着的可选字段照样例写 `null`（`speaker`、`sayAfter.liked`、`farewell`）或空数组（`opening`、`extras`）；`startFx` 没有就不写。
